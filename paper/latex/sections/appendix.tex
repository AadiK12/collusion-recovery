\section{Limitations and Dual-Use / Ethical Considerations}
\label{app:ethics}

\paragraph{Intended benefit.}
The work is intended to help operators distinguish an access repair from actual
recovery of independent checking, and to compare bounded countermeasures before
agents receive real approval authority.

\paragraph{Dual-use risk.}
The same knowledge could help an adversary design interaction histories or peer
messages that encourage unsupported approval. We therefore publish a constrained
synthetic audit environment rather than a real operational target, disclose exact
measurement and defense logic, and avoid optimization recipes for evasion. No
model receives access to personal data, production credentials, financial
systems, or real approval actions.

\paragraph{Experimental safeguards.}
All records are synthetic. Model output is treated as untrusted text and is never
executed as code. Provider calls are stateless at the application layer and run at
concurrency one within stage-specific request, retry, token, context, and dollar
ceilings. Every paid boundary uses a separately reviewed single-use authorization
and hard-stops before the next stage. Raw artifacts exclude secrets and private
reasoning traces.

\paragraph{Interpretation risk.}
Calling ordinary error, base-rate learning, or message compliance ``collusion''
would overstate the evidence. The paper therefore reports deterministic behavior
first, reserves causal language for matched interventions, and uses a narrow
confirmation-only configuration-level label. Null, mixed, or successful-repair
findings remain reportable.
