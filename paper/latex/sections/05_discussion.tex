The available hypothesis-bearing evidence consists of the retained block-0 smoke
and a partial formation-only Gate~3 release. Block 0 had C rejection throughout,
identical A/B verdict vectors with perfect restored-evidence metrics, and reject-all
F behavior. Blocks 1 and 2 also completed C with 20/20 rejections, while block 3
C is partial and block 4 is unrun. This makes the v1.1 3/5 threshold logically
unreachable at no more than 2/5, but it does not complete the prespecified Gate~3
assessment. With no complete pilot or post-restoration A/B results beyond block 0,
the evidence does not establish recovery, equivalence, or an absent
history-conditioned effect. The primary estimate is unavailable.

The practical interpretation depends on the joint safety--usefulness pattern. A
positive post-restoration FAR gap with preserved CPA would indicate that restoring
information did not fully restore independent checking under this configuration.
A correction effect would support an inexpensive instruction-level response; an
additional E$-$D effect would support removing prior visible state as part of the
package. Conversely, a tightly bounded recovery gap with strong absolute
performance would be useful evidence that access repair can work in this setting.
None of these possibilities is a universal claim about all agents or deployments.

If FAR falls only because CPA collapses, the intervention trades one failure for
another rather than restoring verification. If the current peer-policy diagnostic
changes behavior, the study supports evaluation-time susceptibility but not the
origin of the formation history effect. If the separate formation-policy study
also shows an effect, it estimates the total pathway induced by peer policy,
truthful feedback, rewards, and resulting transcripts; it still does not identify
mediation of main B$-$A or rule out independent shortcut learning.

\subsection{Limitations}

The task is synthetic and intentionally narrow. Deterministic truth improves
identification but omits the ambiguity, heterogeneous tools, and consequential
actions of deployed workflows. The study uses one task family and initially one
hosted model configuration; model and provider behavior can change over time.

The history treatment is a bundle: evidence availability changes what compliant
action is possible and can alter messages, verdicts, rewards, and later context.
Main B$-$A is therefore a total assigned-regime effect, not a decomposition of its
mechanism. E$-$D is the incremental effect of reset under correction, not reset in
isolation. Scripted peer policies identify responses to experimenter-defined
interventions but cannot demonstrate spontaneous negotiation or private intent.

Visible transcript state is the only memory carrier studied. Disabling provider
conversation state, tools, retrieval, and automatic truncation narrows the causal
object but does not cover hidden provider changes or every deployed memory system.
Small block counts make uncertainty wide; the five-block pilot cannot establish a
meaningful null. Hosted generation is stochastic, and client seeds guarantee only
the deterministic fixture schedule, not identical model outputs.

Gate~3 also ended before its planned hard stop because one provider HTTP 500 was
ambiguous rather than known not to have completed. The unretried outcome and 92
undispatched identities preserve the release boundary but leave the prespecified
assessment incomplete. Selecting v1.2 at this point is therefore an
early-futility methodological deviation, not an automatic completed-gate
transition. We recorded that prospective preparation path before any v1.2
output existed. Its fresh calibration, smoke, Phase~1 formation, and marker-
contingent Phase~2 each require separate authorization, and their data are never
pooled with v1.1. The one-round formation-peer protocol remains separate rather
than being inherited by the two-round fallback.

The current v1.2 implementation is not execution-ready: Gate~1 is an offline
projection without a live controller, static reviewed proposal, authorization
path, or fresh pricing verification; later stages also lack live controllers and
cross-run prerequisite assessments. If the narrow v1.2 5xx retry is eventually
used, remaining under its identity cap does not resolve the scientific
uncertainty. The unseen attempt may have completed and may differ from the
returned retry, so affected identities and unresolved-outcome sensitivity must
remain explicit.

Finally, the confirmation-only operational-collusion label is an explicit
behavioral convention. It is designed to demand more than parallel approval, but
it remains configuration-level and does not establish legal collusion, deception,
conscious intent, or prevalence outside the tested environment.
