The fixed four-recipe study is incomplete. The original continuation stopped on
HTTP 429 after 455 physical attempts. Ten main episodes and six warm-ups finished;
five planned development dyads have not started. These partial observations do
not decide the fixed final-three-episode feasibility criterion.

This additive release finishes the same eight planned development trajectories,
using the same model, prompts, full histories, tasks, policies, seeds, and scoring.
It introduces no new recipe, calibration, prompt search, repair, or extra dyad.
The original minimum-intervention validation rule remains unchanged, including
its two frozen validation schedules and exclusion of the synthetic seeded arm.

The three interrupted episodes must each reconstruct every saved request and
tool output exactly offline. The live adapter checks those same proofs before
its first new request. Previously completed episodes are carried once, explicitly
marked as prior observations. Two completed responses that arrived after the
original dispatcher stopped are consumed once from their archived bodies.
The failed 429 request receives one explicitly accounted new attempt at its exact
reconstructed boundary. There are no automatic retries or context reductions.

The original journal and all old artifacts remain immutable. Its $0.6402 unknown
reservation is carried as an external historical liability, not counted as known
token consumption or silently released. Every new request is reserved under a
distinct resumption identity. The aggregate limits remain $100 V3 exposure,
$250 lifetime exposure, 4,000 V3 physical attempts, and three concurrent requests.

New requests use one shared pre-reservation pacing window of 1,000,000 estimated
units per 60 seconds, a 60-second startup cooldown, and a five-minute queue bound.

request, and counts opaque reasoning through its original response's full output
token allowance. It neither decrypts nor interprets hidden reasoning. Its 10%
headroom is approximate throughput control, not a guarantee about provider token
accounting. The original conservative financial reservation is unchanged.

Before any new request, the new exact release, all three replay proofs, source
and historical inventories, runtime, sandbox, and independent science, security,
and accounting reviews must pass. A new ambiguous provider outcome stops this
